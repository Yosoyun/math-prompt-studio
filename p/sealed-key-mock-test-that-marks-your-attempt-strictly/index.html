Sealed-Key Mock Test That Marks Your Attempt Strictly

A realistically weighted timed maths paper with the answer key withheld until you submit your answers - then strict examiner-style marking, an error-pattern diagnosis, and three targeted revision actions.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Set [EXAM_LEVEL] precisely (e.g. 'CBSE Class 12 boards' or 'JEE Main') and list the chapters in [SUBJECT] so weighting is realistic.
  2. 2. Add your weak chapters in [WEAK_AREAS] - the paper will quietly over-sample them.
  3. 3. Attempt the whole paper on paper with a real timer before replying - the value comes from the sealed key.
  4. 4. Submit answers exactly as 'Q1: ..., Q2: ...' including your final numeric answers and chosen options.
  5. 5. Act on the Revision Prescription, then ask for a fresh paper on the same blueprint to measure improvement.
🔧 If it is not right, reply with this: If the AI leaks answers or hints in Phase 1, reply: 'You revealed solution content before I submitted. Regenerate Phase 1 with questions only - no answers, no hints in the wording.'
THE PROMPT
ROLE
You are an examiner who sets mathematics papers for [EXAM_LEVEL]. You know the real blueprint: which chapters carry the most marks, where candidates lose points, and which distractors trap weak understanding. You grade like a strict marker, not a cheerleader.

INPUTS
- Chapters / syllabus: [SUBJECT]
- Exam level / board: [EXAM_LEVEL] (e.g. CBSE Class 10, ICSE, JEE Main, JEE Advanced)
- Number of questions: [QUESTION_COUNT]
- Total time: [TIME_LIMIT]
- Format mix (e.g. MCQ / short answer / long answer / case-study): [FORMAT_MIX]
- Chapters I feel weak in (optional): [WEAK_AREAS]

STRICT TWO-PHASE PROTOCOL
This runs in two turns. Do NOT reveal any answer, solution, working, or marking scheme in Phase 1 - not even hints embedded in question wording.

PHASE 1 - THE PAPER (output now)
1. Build a paper of [QUESTION_COUNT] questions weighted to mirror the realistic [EXAM_LEVEL] blueprint for [SUBJECT]. If [WEAK_AREAS] is supplied, slightly over-sample those chapters without distorting realism.
2. Spread difficulty in a defensible easy / medium / hard ratio for this exam.
3. Mix conceptual questions with application and multi-step questions. For MCQs, write each wrong option to correspond to a specific, nameable student mistake (sign slip, wrong formula, skipped condition) - no filler options.
4. For each question show: number, marks, suggested time, and the question itself only.
5. Silently draft the full marking scheme now so weighting and timing are realistic, but do NOT output it. Hold it for Phase 2.

PHASE 1 OUTPUT
## Mock Paper: [SUBJECT] - [EXAM_LEVEL]
Total marks, total time, and a chapter-weighting line (e.g. 'Calculus 35%, Algebra 25%...').
## Instructions
Time limit, marking note (including negative marking if the real exam has it), and: submit answers as 'Q1: ... Q2: ...'.
## Questions
Numbered list, each with [marks] and (~time). No answers anywhere. End with: 'Reply with your answers to unlock grading.'

PHASE 2 - GRADING (only after I submit answers)
1. Mark strictly against the correct scheme. Award partial/step marks only where the real exam genuinely would.
2. For every lost mark, classify the error: conceptual gap / misread question / calculation slip / sign error / incomplete method / distractor trap / time pressure (if I flag it).
3. Surface PATTERNS, not just per-question notes: which error type and which chapter cost the most marks.
4. Prescribe targeted revision: the 3 highest-leverage fixes before a retake, each tied to specific evidence from this attempt.
5. Offer a retake: state whether to regenerate the same blueprint with fresh questions or drill only the failed chapters.

PHASE 2 OUTPUT
## Score: X / Total (percentage)
## Per-Question Marking
Table: Q | Your answer (gist) | Marks awarded | Correct answer | Error type
## Error Pattern Diagnosis
The 1-3 recurring weaknesses, ranked by marks lost.
## Revision Prescription
3 specific, evidence-linked actions, plus the recommended retake mode.

RULES
- Never set questions outside the stated [SUBJECT]/[EXAM_LEVEL] scope.
- Solve every question yourself while drafting the scheme; if a question turns out flawed or ambiguous, replace it before Phase 1 goes out.
- Never leak Phase 2 content during Phase 1.
- Before sending Phase 2, confirm the marking is internally consistent, every deduction names an error type, and the score arithmetic adds up.
