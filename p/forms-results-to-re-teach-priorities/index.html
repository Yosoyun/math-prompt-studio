Forms Results to Re-Teach Priorities

A question-wise analysis of an exported Google Forms CSV with difficulty, distractor patterns and a ranked re-teach list.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Export the response sheet as CSV and remove names, emails and unnecessary identifiers.
  2. 2. Paste the CSV with the exact answer key and marks scheme.
  3. 3. Check the proposed column mapping before trusting any metric.
  4. 4. Recalculate one item manually and use the ranked list to plan a focused re-teach.
🔧 If it is not right, reply with this: If wrong, reply with: "Re-map the actual CSV headers, recompute each item from raw responses and show one manual arithmetic check before ranking re-teach priorities."
THE PROMPT
ROLE: Act as a careful assessment-data analyst, answer-key auditor and re-teach planner.

CONTEXT: A teacher has exported [GOOGLE FORMS RESULTS CSV] and needs trustworthy item analysis for [CLASS OR BATCH] without exposing student identities.

INPUTS — FILL EVERY PLACEHOLDER:
- [GOOGLE FORMS RESULTS CSV]
- [ANSWER KEY]
- [MARKS SCHEME]
- [QUESTION-TO-TOPIC MAP]
- [CLASS OR BATCH]
- [RE-TEACH TIME AVAILABLE]

DO THIS:
1. Validate the header row, row count, missing responses and answer-key coverage before calculating anything.
2. Propose an explicit source-column map and stop rather than guessing when two columns are ambiguous.
3. Audit each numerical answer key with a check-this-yourself link before scoring responses.
4. Calculate attempts, correct count, correct percentage, blank percentage and distractor frequencies for every item.
5. Calculate discrimination only when the dataset and total-score field support it, and label small-sample metrics cautiously.
6. Output paste-ready item-analysis rows and Google Sheets formulas tied to the actual mapped columns.
7. Rank a re-teach list by error rate, misconception severity and topic dependency, then suggest one action per priority.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Analyse responses to an item asking for the mean of 4, 6, 6, 8 and 11.
Expected result or check target: The checked key is 7; response frequencies are compared with 7 before the item is placed in the re-teach ranking.
check this yourself
CHECK → https://www.wolframalpha.com/input?i=mean%204%2C6%2C6%2C8%2C11
(paste-fallback: mean 4,6,6,8,11)
Encoding note: The space is %20 and each comma is %2C.

OUTPUT FORMAT:
1. DATA QUALITY CHECK
2. COLUMN MAP FOR CONFIRMATION
3. ANSWER-KEY VERIFICATION LINKS
4. ITEM ANALYSIS TABLE
5. PASTE-READY SHEETS FORMULAS
6. RANKED RE-TEACH LIST
7. ONE-ITEM MANUAL CHECK

QUALITY AND TOOL GUARDRAILS:
- This prompt analyses an exported Forms CSV; do not output or imply a form-creation URL.
- Never invent missing responses, answer keys, headers or student identifiers, and never expose personal data in the report.
- Show formulas and denominators, distinguish blanks from wrong answers and warn when the sample is too small for stable discrimination.
- Use allowed check links only for the mathematical key and label them check this yourself.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
