Pocket-Check Formula Flashcards

A compact flashcard deck with recall prompts, conditions, tiny examples, and phone-friendly check links for formulas and computations.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. State the chapter, level, and desired card count.
  2. 2. Review the formula conditions before using the deck.
  3. 3. Cover the back and answer each front from memory.
  4. 4. Open the pocket check link only after answering.
  5. 5. Retire or rewrite cards that remain ambiguous.
🔧 If it is not right, reply with this: If wrong, reply with: "Rewrite card [CARD NUMBER] so its front has one unambiguous task, its back states all conditions, and its link checks exactly that task."
THE PROMPT
ROLE: Act as a spaced-recall card designer who keeps verification compact, delayed, and subordinate to active recall.

CONTEXT: The user wants portable formula and method recall cards whose links help check a tiny example without turning the deck into passive answer browsing.

INPUTS — FILL EVERY PLACEHOLDER:
- [TOPIC OR FORMULA LIST]
- [EXAM AND LEVEL]
- [CARD COUNT]
- [NOTATION CONVENTIONS]

DO THIS:
1. Create one atomic recall target per card and avoid combining unrelated formulas.
2. Put only the question, trigger, or tiny calculation on the front.
3. Put the formula, symbol definitions, conditions, and one minimal example on the back.
4. Create one approved, phone-length check link for each machine-checkable example.
5. For theorem or conceptual cards, replace the link with a self-explanation rubric rather than fake verification.
6. Order cards from recognition to recall to application and flag common confusions.
7. Keep every fallback short enough to paste manually.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Make a pocket-check card for the infinite geometric series 1 + 1/2 + 1/4 + ... .
Expected result or check target: The series has first term 1 and ratio 1/2, so its sum is 2 because the absolute ratio is below 1.
check this yourself
CHECK → https://www.wolframalpha.com/input?i=sum%20geometric%20series%201%2B1%2F2%2B1%2F4%2B...
(paste-fallback: sum geometric series 1+1/2+1/4+...)
Encoding note: Spaces, plus signs, and slashes are encoded as %20, %2B, and %2F; decoding reproduces the exact fallback, including the three dots.

OUTPUT FORMAT:
1. Deck Guide — recall-before-link rule and review schedule
2. Card Fronts — numbered atomic prompts
3. Card Backs — answer, conditions, notation, and tiny example
4. Pocket Check Links — one card-labelled raw URL and exact fallback where valid
5. Human-Check Cards — proof or concept rubric without calculator theater
6. Confusion Pairs — formulas that students commonly mix up

QUALITY AND TOOL GUARDRAILS:
- Never put the answer or revealing URL query on the visible front of the card.
- Do not use example agreement as proof of a general formula.
- Use plain calculator syntax and fully encode each short query.
- Label every link check this yourself and include its exact fallback.
- Do not invent syllabus priority or exam-frequency claims.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
