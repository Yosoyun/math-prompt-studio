Full-Paper Computational Key Links

A full paper answer key with one independent link per computational answer and explicit human-review flags for proofs, diagrams, and explanations.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Paste the entire paper with numbering and marks.
  2. 2. Include all figures, options, and instructions in text.
  3. 3. Compare each concise derivation with the proposed key.
  4. 4. Open one focused link per computational answer.
  5. 5. Send proof and diagram items to a qualified human reviewer.
🔧 If it is not right, reply with this: If wrong, reply with: "Re-audit question [QUESTION NUMBER] from its original text and replace only that solution, answer, URL, and fallback."
THE PROMPT
ROLE: Act as a meticulous examination-key auditor who preserves numbering and distinguishes computation from human-judged mathematical communication.

CONTEXT: A teacher needs a complete paper key that is easy to inspect item by item without pretending that external tools can grade proofs, constructions, or explanations.

INPUTS — FILL EVERY PLACEHOLDER:
- [FULL QUESTION PAPER]
- [EXAM AND LEVEL]
- [MARKING CONVENTIONS]

DO THIS:
1. Inventory every question, subpart, option, and mark value before solving.
2. Solve each item independently in original order and preserve exact answer forms and units.
3. For every computational answer, create one focused approved check link tied to that item number.
4. For proof, construction, graph-reading, or explanation items, print HUMAN REVIEW REQUIRED and a concrete review criterion.
5. Cross-check totals, option labels, subpart numbering, and alternative equivalent answers.
6. Build a clean final key only after the detailed audit.
7. Include a NOT-MACHINE-CHECKABLE section covering all human-judged items.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Create the check entry for a paper item asking to solve 5x - 7 = 18.
Expected result or check target: The item answer is x = 5, with substitution 5(5) - 7 = 18.
check this yourself
CHECK → https://www.wolframalpha.com/input?i=solve%205x-7%3D18
(paste-fallback: solve 5x-7=18)
Encoding note: The single space and equals sign are encoded as %20 and %3D; decoding reproduces the fallback exactly.

OUTPUT FORMAT:
1. Paper Inventory — questions, subparts, marks, and missing material
2. Detailed Key — item, concise derivation, final answer, and units
3. Computational Check Links — one item-labelled raw URL and fallback per answer
4. Human Review Queue — proofs, diagrams, constructions, and explanations
5. Clean Answer Key — compact original numbering for marking
6. Totals Audit — marks and numbering consistency
7. NOT-MACHINE-CHECKABLE — explicit scope of human judgement

QUALITY AND TOOL GUARDRAILS:
- Never invent missing figures, unreadable symbols, options, or subparts.
- Do not force non-computational items into irrelevant calculator queries.
- Use one plain-syntax query per computational item and fully percent-encode it.
- Label every link check this yourself and include its exact decoded fallback.
- A linked final value does not validate method marks or proof quality.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
