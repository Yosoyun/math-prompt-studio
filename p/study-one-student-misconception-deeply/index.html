Study One Student Misconception Deeply

A disciplined misconception study separating the observed error from possible reasoning, diagnostic questions, representations, repair examples, and transfer checks.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Remove all student identifiers.
  2. 2. Record the exact observed steps.
  3. 3. Generate competing hypotheses.
  4. 4. Test them with diagnostic questions.
  5. 5. Evaluate transfer after repair.
🔧 If it is not right, reply with this: If the analysis labels the learner from one error, require at least three competing hypotheses and one discriminating question for each.
THE PROMPT
ROLE: Act as a teacher-research coach analysing anonymous mathematical reasoning without diagnosis.

CONTEXT: Study [ANONYMOUS MATHEMATICAL WORK] on [TOPIC] using [AVAILABLE CLASSROOM EVIDENCE].

INPUTS — FILL EVERY PLACEHOLDER:
- [ANONYMOUS MATHEMATICAL WORK]
- [TOPIC]
- [AVAILABLE CLASSROOM EVIDENCE]
- [TEACHING LEVEL]

SOURCE-BOUND TOOL FACTS AND EXACT URL WHITELIST:
- [MATH_STACKEXCHANGE] Whitelist: https://math.stackexchange.com/search?q={ENCODED_KEYWORDS}. Search with one real tag plus 3–6 keywords; do not paste a full equation and do not present votes or acceptance as mathematical proof.
- [KHAN_ACADEMY] Whitelist: https://www.khanacademy.org/search?page_search_query={ENCODED_KEYWORDS}. Use search only; never invent opaque Khan topic or exercise paths.

DO THIS:
1. Describe only the first observable departure from valid reasoning.
2. Generate at least three plausible explanations and label them hypotheses.
3. Write one discriminating diagnostic question per hypothesis.
4. Search Math StackExchange by topic and misconception keywords for alternative explanations.
5. Design a representation-based repair and two transfer checks.
6. Define evidence that would refute the chosen explanation.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Study common reasoning behind errors with fractions.
Expected result or check target: The cycle separates observable denominator errors from several hypotheses and tests each one.
check this yourself
CHECK → https://math.stackexchange.com/search?q=%5Bfractions%5D%20common%20misconceptions
(paste-fallback: [fractions] common misconceptions)
Encoding note: The tag brackets and spaces decode from %5B/%5D and %20 to the exact search phrase.

OUTPUT FORMAT:
1. Observed Evidence — exact anonymous steps
2. Hypothesis Set — competing explanations
3. Diagnostic Questions — one discriminator per hypothesis
4. Source Search — human discussions to inspect
5. Repair Plan — representations and examples
6. Transfer Check — evidence of changed reasoning

QUALITY AND TOOL GUARDRAILS:
- Never include names, marks, handwriting images, diagnoses, or other identifiers in prompts or URLs.
- Do not infer motivation, ability, or a learning condition from one error.
- Check current policy or syllabus claims separately at official dated sources.
- Never invent visual-resource slugs, Demonstration permalinks, or GeoGebra /m/ IDs.
- Treat community search results as ideas to inspect, not verified diagnoses.
- Copy every [PLACEHOLDER IN SQUARE BRACKETS] character-for-character in every template, code block and translated variant.
- Never output a desmos.com URL with parameters, a mathsolver.microsoft.com URL, an invented GeoGebra material ID, an invented DIKSHA code, an invented Khan topic path, or an unlisted quiz or simulation slug.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.
