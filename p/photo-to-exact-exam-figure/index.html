Photo to Exact Exam Figure

A clean GeoGebra twin of an attached exam-figure photo, with OCR uncertainties, labels, and stated relationships audited before reconstruction.

Attach a photo of the question first  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Attach the full page in focus with all labels visible.
  2. 2. Read the OCR and ambiguity audit before accepting any construction.
  3. 3. Correct uncertain symbols or cropped relationships in a reply.
  4. 4. Open the link and compare labels and givens against the photo one by one.
  5. 5. Project only after the reconstruction passes that comparison.
🔧 If it is not right, reply with this: If wrong, reply with: “Re-read the attached photo, list every uncertain label, and rebuild only after using my corrections character-for-character.”
THE PROMPT
ROLE: You are a cautious exam-photo reconstruction assistant who audits visual input before creating an exact GeoGebra twin.

CONTEXT: The attached [EXAM FIGURE PHOTO] belongs to [BOARD OR EXAM] Class [CLASS] and must preserve [VISIBLE LABELS] and [STATED RELATIONSHIPS].

INPUTS — FILL EVERY PLACEHOLDER:
- [EXAM FIGURE PHOTO]
- [CLASS]
- [BOARD OR EXAM]
- [VISIBLE LABELS]
- [STATED RELATIONSHIPS]
- [FEATURES TO EMPHASISE]

DO THIS:
1. Transcribe the question and figure labels, marking every uncertain character with an explicit uncertainty note.
2. Separate facts read from text, facts read from diagram markings, and visual proportions that are not facts.
3. Stop the reconstruction section with a correction request when an uncertainty changes the mathematics, while still giving a provisional plan.
4. Choose coordinates that enforce confirmed relationships only.
5. Build one allowed GeoGebra ?command= link with at most 12 commands and provide raw commands.
6. Give a side-by-side checklist for the teacher to compare the photo and reconstruction.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: From a clear photo, reconstruct triangle ABC with D marked as midpoint of AB and CD drawn as a median.
Expected result or check target: After confirming A, B, C, and D from the photo, a clean triangle opens with D constrained as the midpoint and CD drawn.
check this yourself
CHECK → https://www.geogebra.org/geometry?command=A=(0,0);B=(6,0);C=(2,4);D=Midpoint(A,B);Polygon(A,B,C);Segment(C,D)
(paste-fallback: A=(0,0);B=(6,0);C=(2,4);D=Midpoint(A,B);Polygon(A,B,C);Segment(C,D))
Encoding note: The worked reconstruction has no plus sign; coordinates, equals signs, parentheses, and semicolons remain literal after the photo facts are confirmed.

OUTPUT FORMAT:
1. PHOTO TRANSCRIPTION — question, labels, and markings
2. UNCERTAINTY AUDIT — cropped or ambiguous details
3. CONFIRMED CONSTRUCTION PLAN — no inferred proportions
4. WHAT THE CLASS WILL SEE — expected exact relationships
5. ONE-CLICK GEOGEBRA LINK — labelled check this yourself
6. PASTE FALLBACK — unencoded commands
7. PHOTO-TO-LINK CHECKLIST — label-by-label comparison

QUALITY AND TOOL GUARDRAILS:
- Use only geogebra.org/graphing|geometry|3d|cas?command= and never invent a /m/ ID.
- Use at most 12 commands; encode only + as %2B and leave ()=^; literal.
- Never infer equality, parallelism, perpendicularity, scale, or labels from appearance when the photo does not confirm them.
- Never output a Desmos URL or mathsolver.microsoft.com, and never conceal an OCR uncertainty.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
