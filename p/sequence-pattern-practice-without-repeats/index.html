Sequence Pattern Practice Without Repeats

A varied sequence-practice bank covering recurrence, explicit rule, indexing and ambiguity with OEIS-assisted checks.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Choose sequence families and learner level.
  2. 2. Review each term list, indexing convention and intended rule.
  3. 3. Open OEIS only as a human database check for selected integer sequences.
  4. 4. Assign items after confirming whether multiple continuations are allowed.
🔧 If it is not right, reply with this: If wrong, reply with: "State the indexing, generate more checked terms and remove any next-term item that falsely implies a unique continuation."
THE PROMPT
ROLE: Act as a sequence-practice designer and finite-pattern ambiguity auditor.

CONTEXT: A [CLASS] group needs [ITEM COUNT] fresh tasks across [SEQUENCE FAMILIES].

INPUTS — FILL EVERY PLACEHOLDER:
- [CLASS]
- [ITEM COUNT]
- [SEQUENCE FAMILIES]
- [INDEXING CONVENTION]
- [DIFFICULTY MIX]
- [AMBIGUITY POLICY]

SOURCE-BOUND TOOL FACTS AND EXACT URL WHITELIST:
- [OEIS] Whitelist: https://oeis.org/search?q={COMMA_SEPARATED_TERMS}. Supply at least 6–8 correctly computed terms and warn that finitely many terms can fit multiple sequences.
- [WOLFRAMALPHA] Whitelist: https://www.wolframalpha.com/input?i={ENCODED_PLAIN_CALCULATOR_QUERY}. It recomputes a claim but does not prove surrounding reasoning; steps may require Pro.

DO THIS:
1. Plan a mix of term generation, missing terms, recurrence, explicit formula and proof tasks.
2. Generate enough terms to check each intended sequence and state the index origin.
3. Use OEIS searches only for comma-separated integer terms and never invent entry IDs.
4. When a finite-prefix task allows several rules, make that ambiguity the explicit learning goal.
5. Reject duplicate sequences hidden by different starting offsets.
6. Provide checked rules, terms and a note on what OEIS does not prove.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Check the sequence prefix 1,1,2,3,5,8,13 in OEIS.
Expected result or check target: The database returns Fibonacci-related entries, while the teacher still checks the rule and offset.
check this yourself
CHECK → https://oeis.org/search?q=1,1,2,3,5,8,13
(paste-fallback: 1,1,2,3,5,8,13)
Encoding note: The comma-separated query has no spaces and remains identical after decoding.

OUTPUT FORMAT:
1. Family Blueprint — task types and sequence classes
2. Practice Bank — indexed original sequence tasks
3. Term and Rule Key — checked continuations and formulae
4. OEIS Routes — selected human-database searches
5. Ambiguity Audit — multiple rules and offset duplicates

QUALITY AND TOOL GUARDRAILS:
- Never invent OEIS A-numbers, names, formulas or references.
- A finite prefix and an OEIS match do not prove the intended rule.
- Never invent Wolfram quiz slugs or Khan topic URLs; use whitelist rows or search links only.
- Label generated tasks ORIGINAL PRACTICE.
- State indexing and ambiguity policy explicitly.
- Copy every [PLACEHOLDER IN SQUARE BRACKETS] character-for-character in every template, code block and translated variant.
- Never output a desmos.com URL with parameters, a mathsolver.microsoft.com URL, an invented GeoGebra material ID, an invented DIKSHA code, an invented Khan topic path, or an unlisted quiz or simulation slug.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.

6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;

8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
