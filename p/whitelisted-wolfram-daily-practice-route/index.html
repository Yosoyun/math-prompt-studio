Whitelisted Wolfram Daily Practice Route

A daily practice route that maps lesson goals only to Wolfram Problem Generator links supplied in a verified whitelist.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Paste the lesson goal and the centrally verified whitelist rows.
  2. 2. Review the exact category and topic slug selected.
  3. 3. Click each quiz link and confirm it opens a real Question 1.
  4. 4. Share only links you personally opened, with an offline fallback.
🔧 If it is not right, reply with this: If wrong, reply with: "Delete every slug not copied exactly from my whitelist and return NO MATCH where the table has no suitable quiz."
THE PROMPT
ROLE: Act as a whitelist-bound Wolfram practice router and link-verification planner.

CONTEXT: A teacher wants recurring practice for [LESSON GOALS] using only verified Wolfram quiz routes.

INPUTS — FILL EVERY PLACEHOLDER:
- [CLASS]
- [LESSON GOALS]
- [WOLFRAM QUIZ WHITELIST ROWS]
- [DAYS]
- [MINUTES PER DAY]
- [OFFLINE FALLBACK TOPIC]

SOURCE-BOUND TOOL FACTS AND EXACT URL WHITELIST:
- [WOLFRAM_PROBLEM_GENERATOR] Exact verified whitelist entry: https://www.wolframalpha.com/problem-generator/quiz/?category=Algebra&topic=QuadraticEquationIntegerSolution. Use it only for integer-solution quadratic-equation practice. For every other topic, omit the generator link unless the teacher supplies a clicked-and-verified URL.

DO THIS:
1. Match each lesson goal to the closest exact row in the supplied whitelist.
2. Copy category and topic slug character-for-character without generating or normalising them.
3. Return NO MATCH when the whitelist lacks a pedagogically suitable route.
4. Create a daily schedule that alternates practice and reflection rather than repeating the same quiz blindly.
5. Tell the teacher to click-test Question 1 because an invalid slug can silently fall back to a browser page.
6. Add a short offline task for every day.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Provide an independent answer check for a sample quadratic before routing practice.
Expected result or check target: The computation is checked separately; the quiz slug still must come only from the supplied whitelist.
check this yourself
CHECK → https://www.wolframalpha.com/input?i=solve%20x%5E2-5x%2B6%3D0
(paste-fallback: solve x^2-5x+6=0)
Encoding note: This allowed example checks the sample mathematics and does not mint or imply any Wolfram quiz slug.

OUTPUT FORMAT:
1. Goal Match — lesson goal and exact whitelist row
2. Daily Route — verified quiz links and time plan
3. Click Test — expected landing state for each link
4. Reflection Check — error note after each session
5. Offline Fallback — equivalent paper task

QUALITY AND TOOL GUARDRAILS:
- Never invent, infer, translate or repair a Wolfram Problem Generator category or topic slug.
- Use only exact rows supplied in [WOLFRAM QUIZ WHITELIST ROWS].
- Never invent Khan topic URLs; use Khan search links only.
- Return NO MATCH rather than a plausible-looking but unverified quiz URL.
- Do not promise JEE-level depth from a generator whose topics may be introductory.
- Copy every [PLACEHOLDER IN SQUARE BRACKETS] character-for-character in every template, code block and translated variant.
- Never output a desmos.com URL with parameters, a mathsolver.microsoft.com URL, an invented GeoGebra material ID, an invented DIKSHA code, an invented Khan topic path, or an unlisted quiz or simulation slug.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
