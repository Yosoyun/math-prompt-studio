Breakpoint Error Detective

A line-by-line error trace that identifies the first non-equivalent step and provides a focused link demonstrating the correct computation at that breakpoint.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Paste the question and full attempted work.
  2. 2. Preserve line breaks and numbering.
  3. 3. Review each adjacent-line equivalence verdict.
  4. 4. Open the focused breakpoint check link.
  5. 5. Redo all downstream work from the corrected line.
🔧 If it is not right, reply with this: If wrong, reply with: "Compare only lines [LINE A] and [LINE B] under the original domain and show a counterexample if they are not equivalent."
THE PROMPT
ROLE: Act as a mathematical debugger who finds the earliest consequential break rather than merely comparing final answers.

CONTEXT: The user has a worked solution with an error and needs to know exactly where validity first fails and how to repair the chain.

INPUTS — FILL EVERY PLACEHOLDER:
- [ORIGINAL QUESTION]
- [NUMBERED ATTEMPT]
- [DOMAIN AND CONDITIONS]

DO THIS:
1. Restate the original target and annotate the attempt with stable line numbers.
2. Compare each line to the immediately preceding line for equivalence under the stated domain.
3. Mark valid lines VALID and stop the main diagnosis at the first INVALID or UNJUSTIFIED transition.
4. Classify the breakpoint as algebra, arithmetic, sign, domain, theorem, logic, transcription, or missing justification.
5. Create one approved link focused on the exact operation at the breakpoint when computable.
6. Give a corrected replacement line and recompute downstream results from there.
7. Explain any proof or logic failure that no calculator link can establish.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Find the error in the claim (x + 2)^2 = x^2 + 4.
Expected result or check target: The expansion omitted the middle term; the correct result is x^2 + 4x + 4.
check this yourself
CHECK → https://www.symbolab.com/solver?query=expand%20%28x%2B2%29%5E2
(paste-fallback: expand (x+2)^2)
Encoding note: The space, parentheses, plus, and caret are encoded; decoding gives the exact fallback expression.

OUTPUT FORMAT:
1. Line Map — numbered attempt as received
2. Validity Trace — adjacent-line verdicts up to the breakpoint
3. First Breakpoint — exact transition, error type, and explanation
4. Focused Check — raw link and exact fallback
5. Corrected Continuation — replacement line through final answer
6. Prevention Tip — one specific habit for this error type
7. NOT-MACHINE-CHECKABLE — logical or theorem-based validity

QUALITY AND TOOL GUARDRAILS:
- Do not call later consequences separate root errors once the first breakpoint is found.
- Never infer line equivalence from matching at only a few sample values.
- Use plain calculator syntax and fully percent-encode the focused query.
- Label the link check this yourself and print the exact decoded fallback.
- Keep domain changes and operations such as squaring or division explicit.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
