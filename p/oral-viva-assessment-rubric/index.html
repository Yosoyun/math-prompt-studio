Oral / Viva Assessment Rubric

A rubric and ready question ladder for marking spoken maths answers fairly.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT/Gemini/Claude/Copilot)

✅ How to use this effectively

  1. 1. Open any free AI chat.
  2. 2. Paste the prompt below.
  3. 3. Enter the viva topic and marks.
  4. 4. Send and read the rubric and questions.
  5. 5. Use the same ladder with every student.

THE PROMPT
ROLE: Act as an external examiner who conducts and grades mathematics oral examinations (viva).

CONTEXT: I teach Class [CLASS/GRADE] for [BOARD or EXAM]. I am running an oral / viva assessment on [TOPIC]. Spoken assessment is hard to mark consistently, so I need a rubric plus a fair, graded set of questions to ask every student the same way.

YOUR TASK:
1. Build a rubric out of [TOTAL MARKS] with criteria suited to oral maths, such as: conceptual understanding, correctness of reasoning, ability to explain clearly, response to follow-up probing, and confidence and fluency.
2. Provide a question ladder for this topic with three tiers - easy, medium, hard - and the model answer for each question.
3. Suggest 2 to 3 fair follow-up prompts the examiner can use to probe deeper.
4. Give a simple on-the-spot scoring scale (so the teacher can mark while listening).
5. Add an equity note so every student gets a comparable experience.

INPUT: Topic for the viva: [TOPIC]. Total marks: [TOTAL MARKS]. Time per student: [OPTIONAL e.g. 5 minutes].

HOW TO WORK IT OUT: Solve every model answer internally first, then VERIFY each one by a second method or sanity check so the examiner's key is correct. Confirm the rubric criterion marks add to exactly [TOTAL MARKS]. Never invent facts or formulas. Keep maths legible.

OUTPUT FORMAT, in this exact order:
1. TITLE BLOCK: "Viva Rubric - [TOPIC]", class, total marks, and "Compiled by [YOUR NAME]".
2. RUBRIC TABLE: Criterion | Marks | What earns the marks, with a TOTAL row equal to [TOTAL MARKS].
3. QUESTION LADDER: Easy / Medium / Hard questions, each with a model answer.
4. FOLLOW-UP PROBES (2 to 3).
5. QUICK SCORING SCALE for live marking.
6. EQUITY NOTE (one line on keeping it fair across students).

RULES: Keep the live scoring quick to apply. Every model answer must be verified correct. Questions in each tier must match their difficulty label. State one assumption in a line if the topic is unclear.

OUTPUT FILE FORMAT: present the complete result as a clean, ready-to-use document I can paste straight into Microsoft Word or Google Docs - a clear bold title, section headings, neatly numbered items, comfortable spacing, and simple tables only where helpful (avoid heavy formatting that breaks on paste). It must also print cleanly to PDF on A4 (File > Print > Save as PDF). Keep all mathematics fully readable (fractions as a/b, powers as x^2, roots as sqrt(x)).

MATHS FORMATTING: Write ALL mathematics so it reads correctly in a normal chat and pastes cleanly into Word or Google Docs. Use plain readable notation - for example a/b for fractions, x^2 for powers, sqrt(x) for roots, and symbols like <=, >=, !=, +-, pi, theta, integral and sum. Do NOT output raw LaTeX or code such as \frac{}{}, \sqrt{}, x^{2}, $...$ or \( ... \) - these appear as broken symbols to a teacher in a free chat.

CONTEXT CHECK: Before you begin, if any [SQUARE-BRACKET] above is still empty, or I have not given you the question / photo / data you need, ask me for exactly those and wait - never guess, and never answer with the placeholder text still in brackets.

GROUND RULES (always follow): Do not invent statistics, percentages, marks distributions you were not given, exam cut-offs, solve-time figures, NCERT or textbook page/line numbers, citations, or historical exam data. If you are unsure of any fact or number, say so and clearly label it an estimate; keep established fact separate from your own inference. Every step must be mathematically correct and at the stated class/board/exam level.
