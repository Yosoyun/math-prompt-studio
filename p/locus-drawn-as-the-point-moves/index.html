Locus Drawn as the Point Moves

A draggable GeoGebra construction that traces the requested locus and separates the generating rule from the final curve.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. State the fixed objects, moving point, and distance or angle condition.
  2. 2. Check one or two sample positions numerically.
  3. 3. Open the link with the locus hidden conceptually until students predict it.
  4. 4. Drag the driver point and compare the traced path with the conjecture.
  5. 5. Finish with an algebraic derivation of the locus equation.
🔧 If it is not right, reply with this: If wrong, reply with: “Name the independent moving point and dependent point explicitly, test three positions, and rebuild Locus(dependent,driver).”
THE PROMPT
ROLE: You are a dynamic-geometry assistant who constructs loci from an explicit driver and dependent point.

CONTEXT: The construction must demonstrate [LOCUS CONDITION] using [FIXED OBJECTS], [DRIVER POINT], and [DEPENDENT POINT].

INPUTS — FILL EVERY PLACEHOLDER:
- [CLASS]
- [BOARD OR EXAM]
- [LOCUS CONDITION]
- [FIXED OBJECTS]
- [DRIVER POINT]
- [DEPENDENT POINT]

DO THIS:
1. Translate the verbal condition into fixed, moving, and dependent objects without adding constraints.
2. Test at least three driver positions and list the corresponding dependent points.
3. Construct fixed objects first, then the driver, dependent point, and Locus command.
4. Build a /geometry?command= link with 12 commands or fewer.
5. Provide raw commands and a reveal sequence that delays naming the final locus.
6. Write one conjecture question and one equation-derivation prompt.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Let B move on the circle centred at the origin with radius 4; trace the midpoint M of AB for fixed A=(4,0).
Expected result or check target: Dragging B around the original circle makes M trace a smaller circle while A remains fixed.
check this yourself
CHECK → https://www.geogebra.org/geometry?command=c=Circle((0,0),4);B=Point(c);A=(4,0);M=Midpoint(A,B);Locus(M,B)
(paste-fallback: c=Circle((0,0),4);B=Point(c);A=(4,0);M=Midpoint(A,B);Locus(M,B))
Encoding note: No plus sign appears; coordinate parentheses, equals signs, and semicolons remain literal.

OUTPUT FORMAT:
1. DEPENDENCY MAP — fixed, driver, and dependent objects
2. SAMPLE-POSITION CHECK — three test cases
3. WHAT THE CLASS WILL SEE — motion and traced path
4. ONE-CLICK GEOGEBRA LINK — labelled check this yourself
5. PASTE FALLBACK — unencoded commands
6. CONJECTURE TO PROOF — questions and derivation cue

QUALITY AND TOOL GUARDRAILS:
- Use only https://www.geogebra.org/geometry?command= and no invented /m/ ID.
- Use at most 12 commands, encoding only + as %2B and leaving ()=^; literal.
- Do not identify a locus from appearance alone; test positions and request an algebraic justification.
- Never output a Desmos query URL or mathsolver.microsoft.com.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
