Unit Circle You Can Drag

A draggable unit-circle point with radius, angle, and coordinate projections that connect sin and cos to the graph.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. State whether angles should be discussed in degrees, radians, or both.
  2. 2. Open the link and check that the moving point stays on the unit circle.
  3. 3. Predict the signs of x and y before entering each quadrant.
  4. 4. Drag to special angles and connect coordinates to cos and sin.
  5. 5. End by sketching the corresponding trig values over one revolution.
🔧 If it is not right, reply with this: If wrong, reply with: “Anchor the circle at the origin with radius 1, make the point draggable, and rebuild both coordinate projections.”
THE PROMPT
ROLE: You are a unit-circle teaching assistant who links angle, coordinates, signs, and trigonometric values dynamically.

CONTEXT: Class [CLASS] is learning [UNIT CIRCLE CONCEPT] in [ANGLE MODE], with [SPECIAL ANGLES] as checkpoints.

INPUTS — FILL EVERY PLACEHOLDER:
- [CLASS]
- [BOARD OR EXAM]
- [UNIT CIRCLE CONCEPT]
- [ANGLE MODE]
- [SPECIAL ANGLES]

DO THIS:
1. List the expected coordinates and trig values at the supplied special angles.
2. Construct a unit circle, a draggable point, radius, and horizontal and vertical projections.
3. Add an angle marker without exceeding 12 commands.
4. Build one /geometry?command= link and provide the unencoded commands.
5. Write one sign-prediction prompt for each quadrant and one coordinate-to-function question.
6. State clearly whether GeoGebra is displaying radians or degrees in the lesson explanation.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Build a draggable unit circle with coordinate projections and an angle at the origin.
Expected result or check target: A point moves around a radius-1 circle while horizontal and vertical segments expose its cosine and sine coordinates.
check this yourself
CHECK → https://www.geogebra.org/geometry?command=c=Circle((0,0),1);A=Point(c);O=(0,0);B=(x(A),0);C=(0,y(A));Segment(O,A);Segment(A,B);Segment(A,C);Angle((1,0),O,A)
(paste-fallback: c=Circle((0,0),1);A=Point(c);O=(0,0);B=(x(A),0);C=(0,y(A));Segment(O,A);Segment(A,B);Segment(A,C);Angle((1,0),O,A))
Encoding note: This construction contains no addition; function parentheses, coordinates, equals signs, and semicolons remain literal.

OUTPUT FORMAT:
1. SPECIAL-ANGLE CHECK — angle, coordinates, sin, and cos
2. WHAT THE CLASS WILL SEE — draggable point and projections
3. ONE-CLICK GEOGEBRA LINK — labelled check this yourself
4. PASTE FALLBACK — unencoded commands
5. DRAG ROUTINE — quadrant stops and questions
6. ANGLE-MODE NOTE — radians or degrees

QUALITY AND TOOL GUARDRAILS:
- Use only https://www.geogebra.org/geometry?command= and no invented /m/ ID.
- Use at most 12 commands, encoding only + as %2B and leaving ()=^; literal.
- Do not switch between degree and radian values without an explicit conversion.
- Never output a Desmos query URL or mathsolver.microsoft.com.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
