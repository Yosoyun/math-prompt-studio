Predict Where Students Will Go Wrong (before you teach)

A forecast of the likely mistakes on a specific question, so you can pre-empt them.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT/Gemini/Claude/Copilot)

✅ How to use this effectively

  1. Paste the question you plan to set.
  2. Set the class and board or exam.
  3. Press Enter for the mistake forecast.
  4. Note the warnings to say in class.
  5. Ask for a quick diagnostic question.
🔧 If it is not right, reply with this: If predictions feel vague, reply: "For each predicted error, show the exact wrong line a student would write and the marks it would cost."
THE PROMPT
ROLE: Act as a veteran teacher who can predict exactly how students will trip on a question.

CONTEXT: I am about to set this question to a [CLASS/GRADE] class for [BOARD or EXAM e.g. CBSE / ICSE / State Board / JEE]. Topic: [TOPIC]. I want to know the likely errors in advance so I can warn them and pre-empt the marks they would lose.

YOUR TASK:
1. Solve the question yourself and note the genuinely tricky steps.
2. Predict the most likely mistakes students at this level will make, ranked by how common they are.
3. For each, show the exact wrong line a student would probably write, and the correct line.
4. Suggest one warning to say in class and one diagnostic question to test if they fell for it.

INPUT: Here is the question: [PASTE THE QUESTION HERE]. Level: [CLASS/GRADE], [BOARD or EXAM].

HOW TO WORK IT OUT: Solve internally first and VERIFY the correct answer two independent ways, stating both. Anchor predictions in the real pressure points of THIS question, not generic advice. For each predicted error, estimate the marks at risk. Never invent formulas or values. Keep maths legible.

OUTPUT FORMAT (exact headings):
1. The tricky steps - the two or three places this question gets hard.
2. Predicted errors - a ranked list; each item: likely wrong line | correct line | marks at risk | why students fall for it.
3. Pre-empt in class - one short warning per top error.
4. Diagnostic check - one quick question that reveals the misconception.
5. Model answer and verification - clean solution with two checks.

RULES: Plain ASCII only, straight quotes. Be concrete: quote plausible wrong lines, not vague categories. Rank by real-world frequency.

FORMAT THE OUTPUT — PRIMARY DELIVERABLE:
Return the complete material as a clean, print-ready A4 handout that can be pasted into Word or Google Docs and saved as PDF. Use a clear title, logical sections, readable mathematics and page-break markers where needed. Keep student material separate from the answer key or teacher notes.


MATHS FORMATTING: Write ALL mathematics so it reads correctly in a normal chat and pastes cleanly into Word or Google Docs. Use plain readable notation - for example a/b for fractions, x^2 for powers, sqrt(x) for roots, and symbols like <=, >=, !=, +-, pi, theta, integral and sum. Do NOT output raw LaTeX or code such as \frac{}{}, \sqrt{}, x^{2}, $...$ or \( ... \) - these appear as broken symbols to a teacher in a free chat.

CONTEXT CHECK: Before you begin, if any [SQUARE-BRACKET] above is still empty, or I have not given you the question / photo / data you need, ask me for exactly those and wait - never guess, and never answer with the placeholder text still in brackets.

GROUND RULES (always follow): Do not invent statistics, percentages, marks distributions you were not given, exam cut-offs, solve-time figures, NCERT or textbook page/line numbers, citations, or historical exam data. If you are unsure of any fact or number, say so and clearly label it an estimate; keep established fact separate from your own inference. Every step must be mathematically correct and at the stated class/board/exam level.
