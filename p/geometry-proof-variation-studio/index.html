Geometry Proof Variation Studio

A family of proof problems that varies givens, conclusions and auxiliary choices without relying on diagram appearance.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Paste the exact model theorem and proof.
  2. 2. Approve the dependency graph and allowed transformations.
  3. 3. Review every new figure description and proof sketch.
  4. 4. Assign variations in order of changed reasoning, not visual complexity.
🔧 If it is not right, reply with this: If wrong, reply with: "Return to the proof dependencies, restore all givens and reject variants solved only by reading an unscaled sketch."
THE PROMPT
ROLE: Act as a geometry proof-variation designer and dependency auditor.

CONTEXT: A teacher wants [VARIANT COUNT] fresh proof tasks derived from [MODEL THEOREM] for [LEARNER LEVEL].

INPUTS — FILL EVERY PLACEHOLDER:
- [MODEL THEOREM]
- [MODEL PROOF]
- [ALLOWED THEOREMS]
- [VARIANT COUNT]
- [LEARNER LEVEL]
- [DIAGRAM LABEL RULES]

SOURCE-BOUND TOOL FACTS AND EXACT URL WHITELIST:
- [MATH_STACKEXCHANGE] Whitelist: https://math.stackexchange.com/search?q={ENCODED_KEYWORDS}. Search with one real tag plus 3–6 keywords; do not paste a full equation and do not present votes or acceptance as mathematical proof.
- [AOPS] Whitelist: https://artofproblemsolving.com/community/q1_{ENCODED_KEYWORDS}. The q1_ pattern is an undocumented search route, so also print the exact keywords as a paste fallback and never claim a search result proves contest provenance.

DO THIS:
1. Map the model proof as givens, lemmas, auxiliary construction and conclusion.
2. Generate variants by changing one dependency at a time: converse, missing step, new auxiliary or transfer context.
3. Write exact figure construction text and never rely on a not-to-scale picture for facts.
4. Produce a proof outline for every variant using only allowed theorems.
5. Reject variants that collapse to the model through renamed points alone.
6. Sequence tasks by the new proof decision each one introduces.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Find human proof discussions for the angle-bisector theorem before designing variations.
Expected result or check target: The teacher inspects several proof routes and uses only checked dependencies in new original tasks.
check this yourself
CHECK → https://math.stackexchange.com/search?q=%5Bgeometry%5D%20angle%20bisector%20theorem%20proof
(paste-fallback: [geometry] angle bisector theorem proof)
Encoding note: The geometry tag and keyword spaces are encoded; the decoded query is a focused human-proof search.

OUTPUT FORMAT:
1. Dependency Graph — givens, lemmas and conclusion
2. Variation Plan — changed reasoning feature by item
3. Student Proof Set — exact labelled tasks
4. Teacher Outlines — valid routes and theorem use
5. Distinctness Audit — why each item is materially new

QUALITY AND TOOL GUARDRAILS:
- Never infer geometric facts from appearance or invent labels absent from the construction.
- Never invent Wolfram quiz slugs or Khan topic URLs; use supplied whitelists or search links only.
- Human proof sources are leads that still require line-by-line checking.
- Label generated problems ORIGINAL PRACTICE.
- Do not call renamed-point copies distinct variants.
- Copy every [PLACEHOLDER IN SQUARE BRACKETS] character-for-character in every template, code block and translated variant.
- Never output a desmos.com URL with parameters, a mathsolver.microsoft.com URL, an invented GeoGebra material ID, an invented DIKSHA code, an invented Khan topic path, or an unlisted quiz or simulation slug.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.
