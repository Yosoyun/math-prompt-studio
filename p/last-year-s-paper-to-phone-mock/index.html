Last Year’s Paper to Phone Mock

A supplied old paper rebuilt as a sectioned phone mock with a verified key and complete FormApp script while preserving its source structure.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Paste the complete paper, including sections, options, marks and any internal choices.
  2. 2. Compare the source map and correct any omitted restriction before approving the digital version.
  3. 3. Open all computational verification links and confirm the final key.
  4. 4. Run the script, submit a test attempt and check section order, scores and confirmation text.
🔧 If it is not right, reply with this: If wrong, reply with: "Rebuild the mock from my supplied paper only, restore every section, mark and restriction, and show a source-parity audit before the script."
THE PROMPT
ROLE: Act as a paper-digitisation editor, answer-key auditor and sectioned Google Forms mock developer.

CONTEXT: A teacher wants to recycle [PAST PAPER] into a phone mock without presenting any unsourced new item as part of the original paper.

INPUTS — FILL EVERY PLACEHOLDER:
- [PAST PAPER]
- [ORIGINAL MARKING SCHEME]
- [CLASS OR EXAM]
- [TIME LIMIT]
- [SECTIONS TO INCLUDE]
- [DIGITISATION NOTES]

DO THIS:
1. Transcribe and map every included question to its source number, section, marks and internal-choice rule.
2. Do not call any newly written replacement an original question; label adaptations clearly.
3. Audit the supplied key independently and add check-this-yourself links for computational results.
4. Generate one complete executable FormApp script with page-break sections, required-state choices that preserve optionality, quiz points and logged URLs.
5. Represent diagrams as teacher-supplied image links or precise text only when the source is unambiguous; never invent a diagram.
6. Give a source-parity checklist and a full-score test response for the teacher.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Digitise a supplied paper item asking for the roots of x^2-4x-5=0.
Expected result or check target: The independently checked roots are -1 and 5, and the digital key preserves the source marks.
check this yourself
CHECK → https://www.wolframalpha.com/input?i=solve%20x%5E2-4x-5%3D0
(paste-fallback: solve x^2-4x-5=0)
Encoding note: The space is %20, ^ is %5E and = is %3D.

OUTPUT FORMAT:
1. SOURCE PAPER MAP
2. KEY AUDIT AND CHECK LINKS
3. DIGITISATION DECISIONS
4. COMPLETE SECTIONED FORMAPP SCRIPT
5. RUN IT — script.google.com → New project → paste → Run → View → Logs
6. SOURCE-PARITY CHECKLIST
7. FULL-SCORE TEST RESPONSE

QUALITY AND TOOL GUARDRAILS:
- Use only the paper the teacher supplies and never label invented content as an authentic past-paper question.
- Output one COMPLETE executable FormApp code block and print exactly: script.google.com → New project → paste → Run → View → Logs.
- Never claim a URL creates the Form and never guess missing diagrams, marks or restrictions.
- Preserve optional questions and section rules instead of making every source item compulsory.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
