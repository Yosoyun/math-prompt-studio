JEE Advanced Multi-Correct Option Audit

A JEE Advanced multi-correct audit that tests every option independently, records conditions, and links each decisive computable claim.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Paste the exact stem and every option.
  2. 2. Include the answer-format and partial-marking convention.
  3. 3. Read each option's independent condition test.
  4. 4. Open the option-labelled check links.
  5. 5. Confirm the final set includes every and only valid option.
🔧 If it is not right, reply with this: If wrong, reply with: "Re-test option [OPTION] independently over the full stated domain and provide either a proof or a valid counterexample."
THE PROMPT
ROLE: Act as a JEE Advanced examiner who treats each option as a separate mathematical proposition.

CONTEXT: Multi-correct questions punish elimination by assumption; the user needs a complete option-by-option proof or counterexample audit with no single-correct shortcut.

INPUTS — FILL EVERY PLACEHOLDER:
- [JEE ADVANCED STEM]
- [OPTIONS A TO D]
- [DOMAIN AND CONDITIONS]
- [MARKING SCHEME]

DO THIS:
1. Parse quantifiers and qualifiers in the stem and in each option, including always, exists, and for all.
2. Test A, B, C, and D independently without using an assumed number of correct choices.
3. For a true option, give a complete justification over the stated domain.
4. For a false option, give a valid counterexample or derive the contradiction.
5. Create a separate approved link for each decisive machine-checkable option claim.
6. State when a tool query only checks a sample or algebraic subclaim and cannot settle the quantifier.
7. Apply the marking scheme only after the mathematical option set is fixed.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Audit the option claiming that x^2 - 5x + 6 is positive exactly when x < 2 or x > 3.
Expected result or check target: The option is true over the reals because the upward-opening quadratic has simple roots 2 and 3 and is positive outside them.
check this yourself
CHECK → https://www.wolframalpha.com/input?i=solve%20x%5E2-5x%2B6%3E0
(paste-fallback: solve x^2-5x+6>0)
Encoding note: The space, caret, plus sign, and greater-than sign are encoded; decoding gives the exact fallback inequality.

OUTPUT FORMAT:
1. Stem Logic — domain, quantifiers, and required selection type
2. Option A Audit — verdict, proof or counterexample, link if applicable
3. Option B Audit — verdict, proof or counterexample, link if applicable
4. Option C Audit — verdict, proof or counterexample, link if applicable
5. Option D Audit — verdict, proof or counterexample, link if applicable
6. Final Option Set — letters only after all audits
7. NOT-MACHINE-CHECKABLE — universal reasoning not settled by samples

QUALITY AND TOOL GUARDRAILS:
- Never stop after finding one true option and never assume a fixed number of correct options.
- Do not use a finite numerical test to establish an option quantified over infinitely many values.
- Use plain calculator syntax and fully percent-encode each focused query.
- Label every link check this yourself and include its exact fallback.
- Keep partial-marking advice separate from the answer-set derivation.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
