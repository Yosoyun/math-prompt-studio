Rehearse a Simulation-Led Mathematics Lesson

A rehearsal plan around one exact curated PhET simulation, including prediction, manipulation sequence, observation table, explanation, and low-bandwidth fallback.

Works on any free AI  ·  Best tool:  Any AI chat (ChatGPT, Claude, Gemini)

✅ How to use this effectively

  1. 1. Supply an exact curated simulation URL.
  2. 2. Open it on the classroom device.
  3. 3. Rehearse the manipulation sequence.
  4. 4. Prepare a static fallback.
  5. 5. Separate observation from explanation.
🔧 If it is not right, reply with this: If the plan assumes a preloaded simulation state, rewrite it as teacher actions after opening because PhET URL parameters select screens and locale, not coefficient values.
THE PROMPT
ROLE: Act as a simulation-led lesson coach using only an exact curated PhET URL.

CONTEXT: Rehearse [LESSON GOAL] for [CLASS] with [CURATED PHET URL] under [DEVICE AND BANDWIDTH LIMITS].

INPUTS — FILL EVERY PLACEHOLDER:
- [LESSON GOAL]
- [CLASS]
- [CURATED PHET URL]
- [DEVICE AND BANDWIDTH LIMITS]
- [LESSON LENGTH]

SOURCE-BOUND TOOL FACTS AND EXACT URL WHITELIST:
- [PHET] Exact verified whitelist entry: https://phet.colorado.edu/sims/html/graphing-quadratics/latest/graphing-quadratics_all.html?locale=en&screens=1. It selects the simulation and screen but cannot preload coefficient values. Do not invent other simulation slugs.
- [KHAN_ACADEMY] Whitelist: https://www.khanacademy.org/search?page_search_query={ENCODED_KEYWORDS}. Use search only; never invent opaque Khan topic or exercise paths.

DO THIS:
1. Confirm that [CURATED PHET URL] is teacher-supplied and pass it through unchanged.
2. Write a prediction before each manipulation and an observation after it.
3. Specify clicks, drags, screens, and reset points without claiming the URL preloads state.
4. Connect observations to mathematical explanations and limitations.
5. Create a low-bandwidth board or paper fallback.
6. End with one transfer question that does not require the simulation.

WORKED LINK EXAMPLE — COPY THIS EXACT ENCODING PATTERN:
Example task: Prepare background practice for exploring how quadratic coefficients change a graph.
Expected result or check target: The lesson pairs predictions and observations with a broad independent practice search.
check this yourself
CHECK → https://www.khanacademy.org/search?page_search_query=quadratic%20graph%20exploration
(paste-fallback: quadratic graph exploration)
Encoding note: Spaces decode from %20 to the exact supplementary search phrase; it does not replace the curated simulation URL.

OUTPUT FORMAT:
1. URL Check — supplied curated simulation and screen
2. Rehearsal Timeline — prediction, action, and observation
3. Teacher Moves — exact manipulation sequence
4. Meaning-Making — observation versus explanation
5. Fallback Plan — low-bandwidth alternative
6. Transfer Check — no-simulation question

QUALITY AND TOOL GUARDRAILS:
- Use only the exact teacher-supplied curated PhET URL; never invent a simulation slug or screen number.
- Do not claim a PhET URL can preload coefficient values or object state.
- Never invent Wolfram Demonstration permalinks or GeoGebra /m/ IDs as alternatives.
- Check current syllabus and policy claims at dated official sources.
- Open the simulation on the actual device before describing it as ready.
- Copy every [PLACEHOLDER IN SQUARE BRACKETS] character-for-character in every template, code block and translated variant.
- Never output a desmos.com URL with parameters, a mathsolver.microsoft.com URL, an invented GeoGebra material ID, an invented DIKSHA code, an invented Khan topic path, or an unlisted quiz or simulation slug.
- Never describe an AI answer as verified. Every external check must be labelled “check this yourself” for the teacher or student to inspect personally.
- Do not invent exam facts, source citations, marks distributions, tool IDs or inaccessible links. Separate mathematical proof from computational checking.

=== TOOL-LINK OUTPUT CONTRACT — follow every rule exactly ===
1. You may output clickable links ONLY to: wolframalpha.com/input?i= · symbolab.com/solver?query= ·
   geogebra.org/graphing|geometry|3d|cas?command= · math.stackexchange.com/search?q= · oeis.org/search?q= ·
   artofproblemsolving.com/community/q1_ · khanacademy.org/search?page_search_query= ·
   overleaf.com/docs?encoded_snip= · latex.codecogs.com/png.image? · docs.google.com/forms/...viewform?usp=pp_url
   (Forms only with entry.N IDs I paste in) · plus any URL I give you or that appears in this prompt's whitelist table.
2. NEVER output: desmos.com links with query strings (they load blank), invented geogebra.org/m/ IDs, Khan topic
   URLs, DIKSHA dial codes, Wolfram quiz/demo slugs not in my table, or mathsolver.microsoft.com (dead site).
3. Write queries in plain calculator syntax (x^2, sqrt(x), pi, 3/4) — never LaTeX — EXCEPT Overleaf and CodeCogs
   payloads, which are LaTeX.
4. Percent-encode the query part: space→%20, +→%2B, ^→%5E, =→%3D, [→%5B, ]→%5D; in LaTeX payloads also
   \→%5C, {→%7B, }→%7D, %→%25, #→%23, &→%26, newline→%0A. GeoGebra ?command= exception: encode ONLY + as %2B;
   leave ( ) = ^ ; as typed.
5. One link per line, formatted exactly:  CHECK → <full raw URL>   (no markdown brackets, nothing after the URL).
6. Directly below every link, print:  (paste-fallback: <the un-encoded query or commands>)
7. Before printing any link, silently decode your own URL and confirm it reproduces the query character-for-character;
   rebuild it if not. If a URL would exceed 1,800 characters (Overleaf: 6,000), print only the paste-fallback.
8. Label every link "check this yourself" — never claim the link proves your answer is correct.
9. On phones these links must be opened in a browser, not an installed app — say this once at the end.
